Overview

A client-server chat system built as a duo project, written in C over UDP sockets. The server dispatches a worker thread per request, and messages carry a 2-bit routing prefix directing them to one of three channels: global (00), room (01), or private (10). Clients can connect through either a GTK graphical interface, with separate panes for global, room, and private logs, or a command-line interface.

Technical Approach

The core is a multithreaded UDP server built on POSIX threads, spawning a worker thread per incoming request rather than a single-threaded event loop. Three extensions sit on top of that base: a circular queue that buffers recent message history so a client reconnecting can replay what it missed, a min-heap monitor that tracks client activity and pings and removes inactive connections, and chat room support with administrative controls for grouping clients and directing messages to a subset of participants rather than broadcasting globally.

Results

The system is functional end to end: message routing across all three channels, history replay on reconnect via the circular queue, inactivity detection via the min-heap monitor, and chat rooms with administrative controls all work as designed, demonstrated through the GTK client shown above.

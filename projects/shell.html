Unix Shell

A functional Unix shell written in C, implementing many of the fundamental features found in shells such as Bash: pipelines, redirection, subshells, and history expansion. Built as a duo project.

Overview

The Unix Shell is a functional shell written in C, built as a duo project, covering the core mechanics of how shells like Bash actually work: launching processes, wiring up pipelines and redirection, batching commands, and expanding history references. The project grew out of Imperial's Software Systems module, where we first covered process creation, scheduling, and inter-process communication at the OS level, and this was a chance to put that theory into practice. The codebase is split into three modules: s3main.c holds the main control loop and entry point, s3.c holds parsing helpers, process launches, redirection plumbing, and pipeline logic, and history.c/.h manages a persistent history database plus expansion logic for !!, !n, and !prefix.

Technical Approach

Every command the shell runs comes down to two system calls: fork(), which clones the running shell process into an identical parent and child, and exec(), which replaces the child's memory image with the program you actually asked to run, so it starts executing that program in place. The shell forks, the child execs the command, and the parent waits for it to finish. If the parent doesn't wait, a finished child process can hang around as a "zombie", a process that has exited but whose entry hasn't been cleaned up in the process table. To avoid that, S3 runs a reap() call in the parent after every foreground command, the grim reaper of the shell, collecting the child's exit status and letting the kernel free it properly rather than leaving zombies behind. Built-ins such as exit are handled directly in the parent rather than forked, since there's no child process to reap for those.

Redirection supports <, >, >>, 2>, 2>>, 2>&1, and &>, all validated before the child process is launched. Semicolon batching splits independent command sequences while respecting parenthesis and quote nesting, and pipe detection is quote-aware so pipelines can combine redirection and subshells correctly. cd supports ., .., - navigation and tilde expansion, with the prompt showing the current working directory as [s3 <cwd>]$.

Two extensions build on that base: parenthesised subshells and nested subshells, and history expansion (!! for the last command, !n for command number n, !prefix for the most recent command starting with a given prefix), plus multi-way redirection with last-wins semantics when a command redirects the same stream more than once.

Results

The shell handles the full feature set end to end: piped and redirected commands, semicolon-batched sequences, nested subshells, and history expansion all work as designed, tested against the same command patterns a user would type into Bash.
